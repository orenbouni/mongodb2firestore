# Repository Review

The Aegis Legends codebase is well-structured, modern, and demonstrates good TypeScript design patterns across data adapters, Express routes, and React UI components. However, there are significant concurrency and transactional consistency risks in the MongoDB adapter when running on standalone deployments, unauthenticated administrative and simulation endpoints, memory leak risks in the background simulation engine, and basic authentication missing from local development UI components. (40 files reviewed)

## Findings

| Severity | Category | Location | Description | Recommendation |
|---|---|---|---|---|
| medium | security | `docker-compose.yml:49` | Mongo Express is configured with `ME_CONFIG_BASICAUTH: 'false'`, leaving the MongoDB admin web interface exposed without authentication when containers are running. | Enable basic authentication by setting `ME_CONFIG_BASICAUTH: 'true'` and providing strong default credentials via `ME_CONFIG_BASICAUTH_USERNAME` and `ME_CONFIG_BASICAUTH_PASSWORD`. |
| high | correctness | `backend/src/adapters/mongoAdapter.ts:350` | In non-replica set MongoDB mode, `completeMatch` modifies lobby state, inserts match records, and bulk-updates player stats across multiple queries without transactional boundaries. A failure during intermediate operations causes database state drift. | Require replica set deployment for transactional paths or implement an explicit rollback / compensation mechanism when multi-document transactions are unavailable. |
| medium | correctness | `backend/src/adapters/mongoAdapter.ts:261` | `equipItem` in `MongoAdapter` performs separate `updateMany` and `updateOne` queries sequentially without locking or transactions, introducing a race condition where concurrent calls can leave multiple or no items marked as equipped. | Perform inventory state updates inside a transaction session or use a single atomic positional array update query. |
| medium | error-handling | `backend/src/adapters/mongoAdapter.ts:462` | In standalone MongoDB mode, `purchaseItem` debits currency first and inserts inventory second. If the server crashes or network breaks after currency debit but before inventory write / refund completion, currency is lost permanently. | Require multi-document transactions for purchase flows or record purchase intents in a separate transactional log. |
| medium | performance | `backend/src/services/simulationService.ts:175` | Completed, stopped, and errored simulation jobs are added to `this.jobs` Map in `SimulationEngine` but are never evicted or pruned, causing unbounded memory growth over time. | Implement an eviction policy (e.g. max job cap or TTL-based cleanup) to delete inactive jobs from `this.jobs`. |
| medium | security | `backend/src/routes/simulation.ts:40` | Public REST endpoints `/api/simulation/start`, `/api/admin/clear`, and `/api/admin/bulk-insert` allow unauthenticated clients to trigger resource-intensive database operations or delete all database records. | Add authentication and authorization middleware (e.g. API keys or JWT tokens with admin scope) to protect simulation and database maintenance routes. |
| low | security | `backend/src/server.ts:32` | The unhandled error middleware responds with `err.message` in 500 error payloads, which can leak implementation details or internal query details to untrusted clients. | Return generic error messages (e.g. 'Internal Server Error') in production responses while logging raw error details to server logs. |
| low | correctness | `backend/src/routes/matches.ts:24` | `joinLobby` and `leaveLobby` default missing player IDs to empty strings (`''`) instead of validating input, leading to unnecessary database queries with invalid identifiers. | Validate request payload fields and return HTTP 400 Bad Request when required parameter `playerId` is missing or invalid. |
| low | maintainability | `backend/src/server.ts:43` | The shutdown handler calls `server.close()` followed immediately by `process.exit(0)` without waiting for HTTP connections to drain via `server.close()` callback. | Await `server.close()` completion in a Promise wrapper before executing remaining resource teardown and process exit. |
